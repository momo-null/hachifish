# Hachimi 研究方案 v1.3（预注册）

> **版本**：v1.3 · 2026-09-29 · 自本版本起冻结；实验启动后正文不再改动，偏差须在最终报告中显式声明
> **定位**：个人研究探索（非商业化）
> **配套**：架构 = `architecture.md`；红线 = `spec/redlines.md`；里程碑 = `milestones.md`

研究探索 · 不 root / 合规 · 零自有服务器（BYOK）· 知识级自升级 ablation · 真机操作

**一句话定位**：以「手机 GUI agent」作为知识级自升级研究的实验场——agent 通过官方
Accessibility 通道操作真机（真实 App、真实环境），执行模式为前台引导/分屏，模型走用户
自购 key（BYOK，零自有服务器），验证「轨迹 → 蒸馏 → 知识注入」是否真实提升任务完成率。

## 1. 研究目标与问题

| 编号 | 研究问题 | 类型 |
|------|----------|------|
| RQ1 | 注入蒸馏知识后，agent 在手机 GUI 任务的完成率/步数/耗时是否显著优于冷启动？ | 主 · 验证 |
| RQ2 | 局部知识（skill）、全局记忆、环境模型三组知识各自的边际贡献（消融）？ | 主 · 消融 |
| RQ3 | 自学蒸馏 vs 人类示教蒸馏，哪种更有效？ | 主 · 对比 |
| RQ4 | 结构化 UI 树定位与纯视觉定位在精度/鲁棒性上的差异？ | 辅 · 工程 |
| RQ5 | 官方无障碍通道在真实任务分布下的工程可行性与性能边界？ | 辅 · 工程 |

**成功标准**：RQ1 在 α=0.05 下完成率显著提升（预期 ≥10pp），RQ2 区分出主导知识组件。

**口径声明**：本域**主判据为 RQ1 口径**（完成率 ≥10pp 显著提升，α=0.05）；步数/耗时/
模型调用次数为**次级指标**。其他域的既有判据与本域口径**并列、互不替代**。

## 2. 总体架构

```plain
模型层（用户自购 key，HTTPS 直连，零自有服务器）
  规划模型 + 视觉模型（均为任意 OpenAI 兼容端点，BYOK）
        ↓ 直连 ↓
内核（Python 子集，嵌入 APK）
  自写极简 ReAct loop（语义参照上游桌面实现；含收尾门控与升级判定子集）
  · 模型客户端（OpenAI 兼容）· 知识层模块（文件式存储，App 私有目录）
  · UI 桥工具面 · 授权门控
        ↓ 原生壳（AccessibilityService + MediaProjection + 前台服务 + 门控 UI + Keystore）↓
操作/观察通道（官方 API，不 root）
  操作：无障碍服务（UI 树 · 控件动作 · 手势 · 截图）
  观察：MediaProjection（录屏式一次授权，连续取帧）
        ↓
真机目标环境：Android 11+
  目标 = 测试/开源 App（避开登录与支付流程）；执行模式：前台引导 / 分屏
```

**选型要点**：内核上机不引入额外原生运行时——核心依赖链在 Android 平台缺少可用 wheel，
故循环逻辑自写；知识层为实验处理组，语义保真优先。原生运行时替换降为**产品化可选优化**，
不进入研究范围。

## 3. 技术选型

| 层 | 选型 | 理由 |
|----|------|------|
| 执行环境 | 真机（Android 11+）；开发调试通道 = 开发机 adb | 操作真实环境；无需云设备成本 |
| 操作通道 | 无障碍服务（UI 树 + 控件动作 + 手势 + 截图） | 官方 API、不 root、用户手动开启（合规） |
| 观察通道 | MediaProjection（录屏模式连续取帧） | 一次授权持续拿帧，作视觉输入与执行回放 |
| UI 桥 | 同原语面双实现：运行时实现｜调试实现（经 adb） | 同一接口两实现，内核零改动切换 |
| 视觉感知 | 通用视觉模型 API | 零部署；UI 树可用时以 UI 树为主，自绘界面视觉兜底（RQ4 评估） |
| 规划模型 | 任意 OpenAI 兼容端点（BYOK） | 低成本、模型无关 |
| 内核/知识 | Python 子集（嵌入 APK）+ 自写极简 loop + 文件式存储 | 知识层语义保真；依赖白名单见红线 R7 |
| 上机载体 | 原生壳（嵌入 Python 解释器） | 无障碍与录屏只能原生实现 |

## 4. 实验设计（RQ1–RQ3 核心）

### 4.1 任务集

15 个任务 × 3 难度层，全部避开登录/支付流程（规避风控与隐私噪声）：

| 难度 | 任务类型 | 步骤数 |
|------|----------|--------|
| L1 简单（5） | 便签创建与格式化；计算器表达式；设置项修改；时钟加闹钟；文件重命名 | 3-5 |
| L2 中等（5） | 示例商城搜索→筛选→加购；图库整理；笔记多页编辑；书签管理；收藏路线 | 6-10 |
| L3 复杂（5） | 跨 App 信息汇总；多条件表单；长流程向导；定时任务编排；多 App 数据对比 | 10+ |

### 4.2 对照条件

| 组 | 条件 | 说明 |
|----|------|------|
| A（对照） | 冷启动，无注入 | 只有系统提示 |
| B（自学） | 注入自学蒸馏知识 | 先成功完成每任务若干次，蒸馏后注入 |
| C（示教） | 注入人类示教轨迹 | 人工录制轨迹蒸馏 |
| D（消融） | B 基础上开关各组知识 | 定位主导知识组件 |

### 4.3 指标与样本量

完成率（卡方/二项检验）、步数/墙钟/token（Mann-Whitney U）、鲁棒性（UI 扰动）、
错误分布（定位/步骤/规划）。每组每任务 ≥30 次：4 组 × 15 任务 × 30 ≈ **1800 次执行**。
状态重置：重装测试 App / `pm clear` / 固定布局；每任务随机顺序，避免顺序效应。

无障碍操作特性（每次动作 50-300ms 异步）纳入耗时指标口径；实验期间设备亮屏常驻、
关闭自动锁屏。

**执行通道**：运行时完全在设备本地（无障碍 + 录屏）；实验自动化由 PC 侧 harness 经
`adb reverse` 驱动设备内核的**仅回环 HTTP API**（产品运行不依赖 PC），状态重置经 adb 自动化。

**注入可复现**：B/C/D 组使用固定知识快照（SHA 校验、只读装载）；实验期间冻结知识更新触发，
防止知识漂移。

**预注册原则**：本文档即预注册；数据与脚本随结果开源。

## 7. 合规与风险清单

| 风险 | 等级 | 缓解 |
|------|------|------|
| 主流 App 风控 | 高 | 只操作测试/开源 App；不碰登录与支付流程；结论不依赖真实账号 |
| 无障碍执行性能 | 中 | 每次动作 50-300ms 纳入指标口径；复杂任务用分屏模式 |
| 前台模式用户观感 | 中 | 前台引导/分屏为显式交互，授权门控 + 可随时中止 |
| 录屏授权 | 中 | 高版本 Android 每次会话需确认；必要时降级为 UI 树自证 |
| 模型 API 隐私 | 中 | 实验数据无真实个人信息；截图/轨迹仅测试 App 内容；key 存设备 Keystore |
| 结论不可复现 | 中 | 预注册 + 全量开源（数据/脚本/APK）+ 注入快照锁定 |
| 无障碍被系统回收/限制 | 低 | 引导加白名单 |
| 极简循环与上游语义漂移 | 低 | 语义上游先行（红线 R6）+ 同构对拍用例 |

## 8. 演进路径

| 阶段 | 形态 | 触发条件 |
|------|------|----------|
| I（当前） | 真机 + 无障碍 + 前台/分屏 + BYOK | — |
| II | 锁屏/空闲队列执行 | 前台模式跑通后；需处理锁屏唤醒与无障碍时序 |
| III | 后台无感执行 | 观察项：平台官方开放后台 UI 自动化——与「不 root」约束冲突，默认不启用 |
| IV | 云设备/多实例 | 仅当出现批量场景且成本模型跑通后 |
| — | 原生运行时替换（产品化可选） | 仅当嵌入式的包体积/启动/运维确证构成问题时启动 |

研究优先原则：本研究只做阶段 I（+II 可选）。阶段 III/IV 与运行时替换不进入研究范围，
仅记录为产品化远期选项。
