## 2. 里程碑定义（六要素）

### M0' 真机环境（0.5 周）

- **目标**：一台 Android 11+ 真机成为可实验状态。
- **入口**：CP0 预注册冻结。
- **DoD**：① 无障碍服务开启并在重启后保持；② 采集链路前置验证：`adb shell screenrecord` 产出非空视频（证明设备取帧管线可用；MediaProjection **完整授权流**属 M1' DoD——M0' 时 Hachimi App 尚不存在，无授权主体）；③ 电池白名单 + 亮屏常驻配置完成；④ 前 5 个测试 App 安装并可手动操作；⑤ 上述四项的 checklist 脚本 + 截图证据归档。
- **验证方式**：`harness/checks/m0_checklist.py`（adb 自动化核对）+ 人工 green-light。
- **依赖**：自有真机一台。
- **风险触发**：无障碍被 ROM 回收 → 换机型优先于写保活 hack（机型清单见评审 §4）。

### M1' Kotlin 桥（2.5 周）

- **目标**：AccessibilityService + MediaProjection 桥，原语面与 u2 同构（架构 §4.1）。
- **入口**：M0' 通过。
- **DoD**：① 8 个原语（observe/tap_by_id/tap_xy/type_text/gesture/screenshot/launch_app/press）全部实现并有单测；② **对拍测试：同一测试 App 同一任务，u2 与 Accessibility 双后端轨迹语义一致率 ≥90%**；③ MediaProjection 完整授权流走通（录屏模式一次授权连续取帧，Android 14+ 每会话确认的降级路径）；④ 每 action 时延实测分布（P50/P95）入文档；⑤ 前台服务 + 通知 + 暂停/停止可用；⑥ GateUI 三级门控可弹出并可记忆白名单。
- **验证方式**：对拍用例脚本（进 harness，永久保留为回归）+ 时延基准脚本。
- **依赖**：桌面 `environments/emulator/backend.py`（参照实现，已有）。
- **风险触发**：节点树语义对不齐超 3 天 → 降级「UI 树 + 归一化坐标」混合原语并记录 ADR；总超期 >1 周 → 触发 §3 收缩 S1。

### M2' Chaquopy 内核（2.5 周，与 M1' 部分并行）

- **目标**：Python 内核子集打进 APK 并在真机运行（架构 §3.2）。
- **入口**：CP1 已完成（spike 定案）；M0' 通过（M1' 可后置联调）。
- **DoD**：① `kernel/` 六模块 + mini_loop + brain_client 移植完成，**PC 侧与桌面知识层对拍通过**（同输入同蒸馏/晋升/注入决策）；② APK 构建（Chaquopy），真机启动并跑通一个无 GUI 的 LLM 调用任务；③ Keystore 存取 key；④ 回环 API 六端点（架构 §4.3）`/health` 200；⑤ `scripts/check_redlines.py`（R7 import 黑名单）跑过；⑥ 包体积与启动耗时记录入文档。
- **验证方式**：PC 对拍用例（pytest）+ 真机冒烟脚本。
- **依赖**：桌面 `omni_core/local/*`（上游）；Chaquopy 15。
- **风险触发**：Chaquopy 与异步 loop 冲突 → 退化为同步调用模型并记录 ADR（不引入线程 hack）。

### M3' 单任务闭环（1 周）

- **目标**：S3/S4 两个执行模式各跑通一个端到端任务。
- **入口**：M1' + M2' 通过。
- **DoD**：① 前台引导模式完成「便签创建提醒」任务（预注册任务集 T1）；② 分屏模式完成 1 个 L2 任务；③ 授权门控实际触发 ≥1 次且白名单生效；④ 暂停/停止即时有效；⑤ 轨迹落盘并可经 `/trajectory/<run_id>` 导出，schema 与桌面对齐；⑥ task_done 强制 verify 生效（人为构造一次假完成被拒绝）。
- **验证方式**：端到端脚本 × 2 + 人工演示录屏。
- **依赖**：M1'、M2'。
- **风险触发**：VLM 定位精度不足 → 启用「UI 树为主、VLM 兜底」并记录（此为预注册 RQ4 的既有设计，非偏差）。

### M4' 实验框架（1.5 周）

- **目标**：1800 次执行所需的全部自动化。
- **入口**：M3' 通过。
- **DoD**：① 15 任务 × 3 难度层全部录入并人工各跑通 1 次；② 4 组条件（A/B/C/D）可配置注入；③ 状态重置自动化（`pm clear`/重装/分屏布局）；④ 随机顺序调度 + 断点续跑（轨迹/检查点落盘）；⑤ 异常恢复：断连重连、无障碍健康检查、失败 run 原地重试标记；⑥ 示教录制器产出 1 条合法轨迹（对照组 C 输入）；⑦ 注入快照工具：冻结 + SHA 校验 + 只读装载。
- **验证方式**：空转 50 run 冒烟（A 组冷启动）零人工干预率 ≥98%。
- **依赖**：M3'；桌面 K2 信号口径。
- **风险触发**：空转干预率超标 → 修 harness 优先于开跑（R9 禁带病实验）。

### M5' 中期实验（1 周）

- **目标**：每组每任务 20 次（共 1200 次），出中期裁决。
- **入口**：M4' 通过；CP0 已冻结（R9）。
- **DoD**：① 1200 次执行完成，失败 run 单独标记；② 中期报告：A vs B 完成率方向 + 步数分布 + 功效复核（检测 10pp 所需样本量重估）；③ CP2 决策落文档：补到 30 / 调整 / 止损。
- **验证方式**：统计脚本（vendor 桌面 `effectiveness.py` 思路，判据按修订③）+ 人工评审。
- **依赖**：M4'。
- **风险触发**：见 §3 规则表。

### M6' 正式实验与报告（1.5 周）

- **目标**：补足 ≥30 次/组/任务（总计约 1800 次），出可开源结论。
- **入口**：CP2 决策 = 续跑。
- **DoD**：① 样本量达标（或 CP2 明确缩减并记录）；② 统计分析完成（卡方/Mann-Whitney，α=0.05）；③ 报告 + 全量数据 + 脚本 + APK 达到可开源状态；④ R12 诚实边界自查：未证明的结论零出现。
- **验证方式**：人工评审 × 2（统计口径 + 诚实边界）。
- **依赖**：M5'。
- **风险触发**：设备中途损坏 → 换机续跑（轨迹落盘设计支持），计入偏差附录。

## 3. 触发规则（CP2 / 每周复盘共用）

| 情形 | 动作 |
|------|------|
| 中期效应方向为正但幅度小 | 按功效复核补样至 30；不动判据（R10） |
| 效应方向为负或零 | 先查注入实现对拍（R6 漂移排查）→ 再谈样本；确认实现无误则如实报告零结论（R12） |
| M1'/M2' 累计超期 >1 周 | 收缩 S1：M3' 先用「u2 调试通道 + Accessibility 截图桥」最小组合开跑，Accessibility 完整桥并入 M4' |
| M4' 空转干预率 <98% | 停跑修 harness；已跑数据作废不计入样本 |
| 任何红线被触犯 | 立即停跑，修复并记录后重新从最近 green-light 里程碑续跑 |

**收缩顺序**（超期时从上往下砍）：S1 Accessibility 桥最小化 → S2 分屏模式变体 → S3 任务集从 15 缩到 10（L1+L2 优先）→ S4 样本 30→20。**不可砍**：对照组结构（A/B/C/D）、预注册判据、状态重置自动化。
