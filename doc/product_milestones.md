# Hachimi 产品里程碑（v1.0）

> **定位**：手机端 GUI agent——用户说一句话，agent 用官方无障碍通道在真机上把事办完。
> **与实验计划的关系**：研究实验（M4' 及以后）已冻结在 12/15 并暂停；本文档是**产品形态**的
> 独立路线，与 `milestones.md`（研究里程碑）并行存在，互不阻塞。研究用的 harness 与任务集保留。
> **纪律**：每里程碑独立可验证、逐个人工 green-light；DoD 未达标不进下一个。

## 0. 产品原则（不可协商）

| # | 原则 | 含义 |
|---|------|------|
| 1 | **官方 API，不 root** | 操作只走 AccessibilityService，观察走 MediaProjection/screenshot；禁 root、私有 hook、反射绕授权（红线 R2） |
| 2 | **BYOK，零自有服务器** | 模型端点与密钥由用户自备，存设备 Keystore；App 只与用户配置的端点通信 |
| 3 | **可随时中止** | 主界面、悬浮面板、通知栏三处都能停；停止即时生效 |
| 4 | **敏感操作门控** | 输入、删除、支付类页面先过授权弹层，支持「总是允许」白名单，且白名单可撤销 |
| 5 | **本地优先** | 轨迹、知识、配置全部落 App 私有目录；无遥测、无埋点 |
| 6 | **模型无关** | 任何 OpenAI 兼容端点都能接入，内核不含厂商专属逻辑 |

## 1. 现状基线（P0 的起点）

**已有且已验证**
- 八原语（observe / tap_by_id / tap_xy / type_text / gesture / screenshot / launch_app / press）
- 真机内核：Python（Chaquopy）+ MiniLoop + 模型客户端 + 轨迹落盘 + task_done 强制校验
- Kotlin 壳：无障碍服务、MediaProjection（取帧已通）、前台服务 + 常驻通知、授权门控弹层、
  悬浮叙事面板（含分屏停靠形态）、Keystore 存 BYOK、回环 HTTP（实验通道）
- 知识层模块（skill_library / world_model / curator / knowledge_inject）已移植，实验期冻结未接线

**没有（产品化的缺口）**
- 手机上没有"下目标 → 运行"的入口（现有 `MainActivity` 是八原语调试页）
- 没有 BYOK 设置页（改端点只能靠调试广播）
- 没有首次授权引导（无障碍 / 悬浮窗 / 录屏三个授权要用户自己找）
- 观察通道只用了无障碍树，没有视觉兜底
- 没有任务历史、没有多轮纠正、没有知识管理 UI

**两条实现约束（设计时已确认）**
- 产品内触发任务走 **Chaquopy 直调**（`KernelHostService.pyBridgeModule` 已缓存 bridge 模块），
  不绕回环 HTTP；但 `/task` 里那段"从 Keystore 读配置 → `set_brain`"的注入必须在直调路径复刻。
- 完成判据留空时不能死锁：走**目标关键短语弱探测**（从 objective 抽关键词做屏幕文本匹配），
  需要把 objective 一并传进校验函数。

## 2. 里程碑定义

### P0 可用：手机上下目标就能跑（1 周）

- **目标**：不连电脑，在手机上完成一个端到端任务。
- **入口**：现状基线。
- **范围**：S2 主界面 + BYOK 设置页 + 首次授权引导（无障碍 / 悬浮窗；录屏延到 P1）。
- **DoD**
  1. 主界面可输入目标与完成判据（判据可留空），有运行 / 暂停 / 停止，实时显示步数、耗时、当前动作
  2. 三类任务（便签创建 / 时钟加闹钟 / 文件重命名）**零 PC 介入**各跑通 1 次
  3. 设置页可填端点 / 密钥 / 模型，保存进 Keystore，重启 App 后仍生效；提供「测试连通」
  4. 无效密钥、断网、模型返回异常时，界面给出**明确可读**的错误，不是静默失败
  5. 无障碍未开启时，主界面有状态指示 + 一键跳转系统设置
  6. 停止在 App 内、悬浮面板、通知栏三处都即时生效
- **验证**：人工在手机上连续跑 3 类任务 + 1 次错误注入（填错密钥）。
- **依赖**：无。
- **风险触发**：Chaquopy 直调的线程问题（叙事回调需回主线程）→ 退回回环 HTTP 直连本机端口。

### P1 观察通道与视觉兜底（1.5 周）

- **目标**：无障碍树看不清的界面（自绘 / 游戏 / 无控件 id）也能操作。
- **入口**：P0 通过。
- **范围**：MediaProjection 连续取帧 → 视觉模型 provider → observe 兜底；分屏控制台形态（S4）。
- **DoD**
  1. 录屏授权流程完整可用（含高版本系统每次会话确认的降级路径）
  2. 取帧延迟与内存占用达标（p95 ≤ 300ms；连续运行 10 分钟无 OOM）
  3. 视觉兜底能完成 ≥1 个无障碍树无法处理的任务
  4. 视觉模型可关闭，关闭后功能退化为 P0 行为（不报错）
  5. 分屏停靠控制台可用，且按钮条不吞目标 App 的底部触摸（已知坑，必须回归）
- **验证**：自绘界面任务 ×1 + 10 分钟连续取帧压测 + 分屏底部可点回归。
- **实证（2026-09-29）**：DoD1 ✓（Android 12 一次授权；重装后 adb 驱动产品 UI+系统弹窗
  重授权 ✓；「高版本每次会话确认」无高版本真机，待验）/ DoD2 ✓（10min×600 帧
  p95=62ms，内存平稳）/ DoD3 ✓（CanvasProbe 纯自绘夹具：a11y 树 8 个裸节点零语义，
  视觉通道 3 击全中，run r1790695702427，8 步 97.5s，hits.log 客观记录 + task_done
  强制校验通过）/ DoD4 ✓（结构性降级 + 用例）/ DoD5 ✓（停靠三连证：渲染实时叙事、
  内容窗触摸穿透、结束自动收起）。**P1 五项 DoD 实证完毕，唯一残留：高版本录屏
  降级子项（环境受限）。**
- **依赖**：P0；用户自备的视觉模型端点。
- **风险触发**：视觉模型成本/延迟不可接受 → 降级为"用户手动触发一次截图分析"，不做全程视觉。

### P1.5 UI 终态化（用户调整优先级插入：先成壳，再进 P2）

- **目标**：产品 UI 一次做到设计稿终态（doc/ux_mockup.html），后续 P2/P3 只填数据不动壳。
- **入口**：P1 通过；2026-09-29 用户拍板调整优先级。
- **范围**：DesignSystem 单一来源 + 8 屏骨架；未接线能力（知识/实验）做**骨架+诚实空态**（用户确认口径）。
- **DoD**
  1. DesignSystem 单一来源，全屏无散落硬编码色
  2. S1 首启四步引导真实可用（未就绪进入→逐项完成→之后不再出现；跳转均为系统官方入口）
  3. S2 全组件 + 分段控件真实切换执行模式 + 最近任务真实历史（bridge.list_tasks_json）
  4. S5 完成态真实数据渲染（成功/失败/停止三态，指标取 status().summary）
  5. S7 四分组：BYOK 双端点（视觉留空=关闭，v3 单端点兼容迁移）/ 执行（默认模式双向同步 + 门控级别）/ 知识诚实占位 / 实验连点入口
  6. 执行中浮条/停靠新视觉 + 时间线染色 + 红框定位指示；门控弹层终态
  7. 知识 Tab/实验模式诚实空态（能力默认关红线文案）
  8. 真机全流程走查零回归（P0 抽查 + 产品 UI 发起任务 + harness smoke）
- **明确不做**：S6/S8/S5 数据填充（P2）、模板/多轮纠正（P3）、dark mode、世界模型内容、App 图标重设计。
- **风险触发**：MainActivity 重写回归 → launcher/KernelHostService 启动/Chaquopy 直调路径原样保留 + smoke 把关。

### P2 知识与记忆：越用越顺手（1 周）

- **目标**：把已移植但未接线的知识层变成产品能力。
- **入口**：P1 通过（或独立并行）。
- **范围**：成功任务的知识沉淀、注入、管理 UI。
- **DoD**
  1. 任务成功后可沉淀知识（默认开启，可在设置里关闭）
  2. 主界面能看出"本次注入了哪些知识"
  3. 知识管理页：查看、启用/停用、删除、一键清空
  4. 同一任务第二次执行，步数可观测下降（自测 A/B 各 3 次）
  5. 知识文件落 App 私有目录，可导出、可随"清空数据"一起删除
- **验证**：同任务重复执行对比 + 知识管理页人工检查。
- **依赖**：P0。
- **风险触发**：知识注入导致行为劣化 → 立刻可关闭，默认改为关闭。

### P3 任务管理与多轮（1 周）

- **目标**：它像一个能用的 App，而不是一次性的脚本。
- **入口**：P0 通过。
- **范围**：任务历史 + 详情回放 + 中途纠正 + 快捷模板。
- **DoD**
  1. 历史列表可查，详情可按步回放（动作 + 当时屏幕树/截图）
  2. 运行中可插入纠正（"改成 7:30"），loop 能接收并继续，不需要从头重跑
  3. 常用任务可存为模板，一键复用
  4. 失败任务可"原样重试"
- **验证**：人工跑 1 个任务 → 中途纠正 → 回放历史。
- **依赖**：P0；**中途纠正需要内核新增消息注入能力**（当前 MiniLoop 无此接口）。
- **风险触发**：消息注入与卡住检测/校验门控冲突 → 拆成"纠正即重启任务"的简化版。

### P4 稳定性与可观测性（1 周）

- **目标**：长时间运行不掉链子，出问题能定位。
- **入口**：P0 + P1。
- **DoD**
  1. 连续运行 30 分钟无崩溃、无内存持续增长
  2. 无障碍被系统回收时**能检测**，主界面给出明确引导（已知部分 ROM 需手动重开）
  3. 模型超时/失败有重试与降级，并在界面说明当前状态（不是转圈到底）
  4. 本地诊断日志可导出（不含密钥、不含密钥明文）
  5. 耗电与发热在可接受区间（与 P1 取帧策略联动）
- **验证**：30 分钟混合任务 + 人为触发一次无障碍回收。
- **依赖**：P0、P1。
- **风险触发**：部分 ROM 回收无障碍无法程序化恢复 → 以"检测 + 引导"为验收，不追求自动恢复。

### P5 安全与隐私（0.5 周）

- **目标**：敢给别人用。
- **入口**：P0。
- **DoD**
  1. 门控白名单可查看、可撤销；敏感操作范围（输入 / 删除 / 支付类页面）可配置
  2. 抓包审计：除用户配置的模型端点外**无任何外发**
  3. 日志与轨迹脱敏，导出时可选"不含屏幕内容"
  4. 提供"清空所有本地数据"（配置 / 知识 / 轨迹）
  5. 权限与数据说明文案就位（每个权限为什么需要）
- **验证**：抓包审计 + 白名单撤销回归 + 清空数据后冷启动。
- **依赖**：P0。

### P6 发布就绪（1 周）

- **目标**：可以拿出去给人装。
- **入口**：P0–P5 全部通过。
- **DoD**
  1. 产品化 UI：图标、名称、主题、空态与错误态文案
  2. release 构建可用（调试桥在 release 失效），体积与冷启动达标
  3. 权限申请时机合理（用时才申请，附解释）
  4. 公开仓库干净：无密钥、无设备标识、无私人文档（已完成）
  5. 一份能让人照着用起来的说明（装 → 配端点 → 开无障碍 → 下第一个任务）
- **验证**：release APK 全流程走一遍新机（或恢复出厂流程）。
- **依赖**：全部。
