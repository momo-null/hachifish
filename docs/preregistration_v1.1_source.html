手机版 OmniAgent 研究方案

版本 v1.1 · 2026-09-25 · 定位：个人研究探索（非商业化）· v1.1 变更：执行形态定稿为「真机 + Accessibility + 前台/分屏」，放弃 root 虚拟副屏路线

研究探索不 root / 合规零服务器（BYOK）知识级自升级 ablation真机操作

一句话定位：把「手机 GUI agent」作为 OmniAgent 知识级自升级研究的实验场——agent 用官方 Accessibility 通道操作真机（真实 App、真实环境），执行模式为前台引导 / 分屏，模型走用户自购 key（BYOK，零服务器），验证「轨迹 → 蒸馏 → skill/记忆注入」是否真实提升任务完成率，填补 X3 遗留的有效性数据缺口。

1. 背景与动机

1.1 为什么是手机

  • 桌面 GUI agent 竞争饱和（UI-TARS Desktop / Claude Computer Use / OpenClaw），差异化窗口已关闭；手机是大众入口。
  • 需求已验证：豆包手机助手 2025-12 技术预览版引爆全网，2026-09 消费者版开售；云手机 + RPA/LLM 模式已有 DuoPlus、红手指、阿里云 Agentic Mobile 等 5+ 家产品。
  • 商业化存在结构性障碍（主流 App 风控、C 端付费意愿低、云手机成本），故以研究切入。

1.2 执行形态决策（v1.1 新增）

  • 参照对象：AcidGr「虚拟副屏操作真机」方案——agent 在独立虚拟副屏操作真机、前台无感。
  • 决策：该方案的副屏隔离渲染依赖 KernelSU 内核 hook（Display 重定向 + 触控流注入），公开 API 无等价物，与「不 root」硬约束冲突，故不采用。
  • 替代：真机 AccessibilityService（官方 API，操作真机）+ MediaProjection（官方 API，观察通道）+ 执行模式前台引导 / 分屏。「前台执行」已被豆包手机助手验证为大众可接受形态。
  • 远期观察项：Android 若开放后台 UI 自动化 API，或接受 root/真机 adb 形态，再评估「无感」升级（见 §9）。

1.3 研究价值主张

  • 知识级自升级有效性 ablation 至今无公开数据；本研究给出第一个可复现量化结论，并消融定位「哪部分知识（skill/记忆/world-model）贡献最大」。

2. 研究目标与问题

编号研究问题类型
RQ1注入蒸馏 skill 后，agent 在手机 GUI 任务的完成率/步数/耗时是否显著优于冷启动？主 · 验证
RQ2skill、全局记忆、world-model 三组知识各自的边际贡献（消融）？主 · 消融
RQ3自学蒸馏 vs 人类示教蒸馏，哪种更有效？主 · 对比
RQ4UI 树定位（Accessibility）与纯视觉定位（VLM）在精度/鲁棒性上的差异？辅 · 工程
RQ5Go so 真机执行链路（JNI + Accessibility）的工程可行性与性能边界？辅 · 工程
成功标准：RQ1 在 α=0.05 下完成率显著提升（预期 ≥10pp），RQ2 区分出主导知识组件，产出可写入 master-spec 的 X4 依据。

4. 技术选型与理由（v1.1 更新）

层选型理由
执行环境真机（Android 8+）；开发调试通道 = 开发机 adb（研究阶段正当用途）操作真实环境；无需云手机/容器成本
操作通道AccessibilityService（UI 树 + performAction + dispatchGesture + 截图）官方 API、不 root、用户手动开启（合规）
观察通道MediaProjection（录屏模式连续取帧）一次授权持续拿帧，作视觉输入与执行回放
UI 桥双实现：Accessibility 实现（真机）｜ U2 实现（开发调试，经 adb 直连）同一接口两实现，内核零改动切换——延续「能力==工具」红线
视觉感知通用 VLM API（豆包视觉/通义 VL/GLM-4V）零部署；UI 树可用时以 UI 树为主，自绘界面 VLM 兜底（RQ4 评估）
规划模型DeepSeek / 豆包 / 任意 OpenAI 兼容端点（BYOK）低成本、模型无关（内核原则 4）
内核/知识Go 重写 omni_core + SQLite与 OmniAgent 架构一致；.so 嵌入 APK（远期真机产品形态前置验证）

5. 实验设计（RQ1–RQ3 核心）

5.1 任务集（真机测试 App）

15 个任务 × 3 难度层，全部避开登录/支付（规避风控与隐私噪声）：

难度示例任务（开源/系统测试 App）步骤数
L1 简单（5）便签创建+格式化；计算器表达式；设置项修改；时钟加闹钟；文件重命名3-5
L2 中等（5）开源商城 demo 搜索→筛选→加购；图库整理；笔记 App 多页编辑；浏览器书签管理；地图 demo 收藏路线6-10
L3 复杂（5）跨 App 信息汇总；多条件表单；长流程向导；定时任务编排；多 App 数据对比10+

5.2 对照条件

组条件说明
A（对照）冷启动，无注入只有系统 prompt
B（自学）注入自学蒸馏 skill先成功完成每任务 3 次，蒸馏后注入
C（示教）注入人类示教轨迹人工录制轨迹蒸馏
D（消融）B 基础上开关 skill/记忆/world-model定位主导知识组件

5.3 指标与样本量

  • 完成率（卡方/二项检验）、步数/墙钟/token（Mann-Whitney U）、鲁棒性（UI 扰动 ±5%）、错误分布（定位/步骤/规划）。
  • 每组每任务 ≥30 次：4 组 × 15 任务 × 30 ≈ 1800 次执行。
  • 状态重置：卸载重装测试 App / 清除数据 / 分屏固定布局；每任务随机顺序，避免顺序效应。
  • 无障碍操作特性（每次 action 50-300ms 异步）纳入耗时指标口径；实验期间手机亮屏常驻、关闭自动锁屏。
预注册原则：本文档即预注册；数据与脚本随结果开源。

8. 合规与风险清单（v1.1 更新）

风险等级缓解
主流 App 风控/封号🔴 高只操作测试/开源 App；不碰主流电商支付；结论不依赖真实账号
无障碍执行性能🟠 中每次 action 50-300ms，纳入指标口径；复杂任务用分屏模式并行不阻塞用户
前台模式用户观感🟡 中前台引导/分屏为显式交互，授权门控 + 可随时中止（研究场景无此问题）
MediaProjection 授权🟡 中Android 14+ 每次会话需确认；研究用录屏模式一次性授权；必要时降级 UI 树自证
LLM API 隐私🟡 中实验数据无真实个人信息；截图/轨迹仅测试 App 内容；key 存本机 Keystore
结论不可复现🟡 中预注册 + 全量开源（数据/脚本/APK）
无障碍被系统回收/限制🟢 低引导加白名单（研究用开发机/自有手机可控）

9. 演进路径（v1.1 更新）

阶段形态触发条件
I（当前）真机 + Accessibility + 前台/分屏 + BYOK—
II锁屏/空闲队列执行（时间维度无感）前台模式跑通后；需处理锁屏唤醒与无障碍时序
III虚拟副屏无感（对标 AcidGr）观察项：Android 官方开放后台 UI 自动化，或接受 root/KernelSU——与「不 root」约束冲突，默认不启用
IV云手机/多实例（规模化）仅当出现付费场景（B 端批量），成本模型跑通后
研究优先原则：本研究只做阶段 I（+II 可选）。阶段 III/IV 不进入研究范围，仅记录为产品化远期选项。
